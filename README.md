# טלוהים — נגן IPTV לטלוויזיה

שתי אפליקציות לאותו שימוש, בריפו אחד:

| תיקייה | פלטפורמה | טכנולוגיה |
| --- | --- | --- |
| `app/` | אנדרואיד, טאבלט ו-Android TV | Kotlin + Jetpack Compose + Media3/ExoPlayer |
| `tizen/` | טלוויזיות Samsung | אפליקציית ווב עם Tizen AVPlayer |

הפיצול הזה אינו כפילות מיותרת: טלוויזיית Samsung מריצה Tizen ולא אנדרואיד, ולכן
היא לא יכולה להתקין APK בכלל — היא צריכה חבילת `.wgt` משלה.

האפליקציה היא **נגן בלבד**: אין בה תוכן, והערוצים מגיעים מרשימה או ממנוי שאתם מחברים.

## התקנה — אנדרואיד

הורדה ישירה, תמיד הבנייה האחרונה:
**https://github.com/mlayfer/New-iptv/releases/latest/download/telohim.apk**

פותחים את הקישור בטלפון או בטלוויזיה, מאשרים "התקנה ממקור לא מוכר" (זו בנייה
חתומה במפתח debug, לא דרך חנות), ומתקינים. בטלוויזיה הכי נוח דרך Downloader, או
`adb install telohim.apk` מהמחשב.

## התקנה — Samsung Tizen

צריך [Tizen Studio](https://developer.tizen.org/development/tizen-studio/download)
ותעודת מפתח (Certificate Manager ← Samsung ← TV).

בטלוויזיה: Apps ← להקליד `12345` בשלט ← Developer mode ← On, ולהזין את כתובת ה-IP
של המחשב. מאתחלים את הטלוויזיה.

כל בנייה מפרסמת גם `telohim-unsigned.wgt` — החבילה בנויה, אבל **לא חתומה**.
טלוויזיית Samsung מתקינה רק חבילה חתומה בתעודה שקשורה לחשבון Samsung שלך ול-DUID
של המכשיר, ולכן זה השלב היחיד שחייב לרוץ אצלך:

```sh
tizen package -t wgt -s <שם-הפרופיל> -- telohim-unsigned.wgt
sdb connect <IP-של-הטלוויזיה>
tizen install -n telohim-unsigned.wgt -t <שם-המכשיר>
```

או לבנות מהמקור, אם נוח יותר:

```sh
cd tizen
tizen build-web -e ".*" -e gitignore
tizen package -t wgt -s <שם-הפרופיל> -- .buildResult
```

`config.xml` מגדיר את מזהה החבילה, ההרשאות (אינטרנט, מקשי שלט) ומצב לרוחב.
מזהה החבילה הוא `MlayferTV2`. שינוי שלו הופך את ההתקנה לאפליקציה אחרת בטלוויזיה,
בדיוק כמו ששינוי `applicationId` היה עושה באנדרואיד — ולכן הוא לא משתנה סתם. הוא
כן שונה פעם אחת, מ-`MlayferTV1`, כשהחבילה הישנה נתקעה על טלוויזיה: היא נחתמה
בתעודה אחת וכל בנייה מאז בתעודה אחרת, Tizen לא מחליף חבילה במקום מעבר לפער כזה,
והמכשיר לא הציג דבר ברשימת האפליקציות שאפשר להסיר.

## איך שתי האפליקציות נשארות זהות

שתי אפליקציות בשתי שפות מתפצלות מעצמן, וזה כבר קרה כאן: לגרסת האנדרואיד היה סולם
כתובות שהציל ערוצים תקינים, ולגרסת הטייזן לא. לכן ההתנהגות המשותפת מתוארת פעם
אחת ב-[`shared/parity/fixtures.json`](shared/parity/fixtures.json) — פירסור M3U,
נירמול כתובת פורטל, וריאציות של נקודות קצה ובניית רשימת פרקים.

שני הצדדים נבדקים מול אותו קובץ: `app/src/test/.../ParityTest.kt` בקוטלין,
`tizen/test/parity.test.js` ב-JavaScript, ושניהם רצים בכל דחיפה. שינוי התנהגות
שנעשה בצד אחד ונשכח בשני מפיל את הבנייה.

הלוגיקה הטהורה בטייזן יושבת ב-`tizen/core.js` ולא בתוך `app.js`, כדי שאפשר יהיה
לבדוק אותה בלי דפדפן.

## פיתוח של מסכי הטלוויזיה

אפשר להריץ את אפליקציית הטייזן בדפדפן רגיל, כולל בגודל של פלייליסט אמיתי:

```sh
cd tizen && python3 -m http.server 5300
# ואז לפתוח http://127.0.0.1:5300/index.html?demo=19000
```

`?demo=N` ממלא את האפליקציה בפריטים מיוצרים. זה קיים כדי לבדוק את הפריסה ואת
הרינדור החלוני בגדלים אמיתיים — הרשימה מציירת חלון של עשרות פריטים בכל רגע, כי
ציור של 19,000 שורות עם לוגו לכל אחת מקפיא טלוויזיה.

## למה נייטיב ולא דפדפן

נגן IPTV שרץ בדפדפן נתקל בשתי חומות שחוסמות ערוצים תקינים לגמרי:

- **CORS** — ספקים לא שולחים כותרות הרשאה, והדפדפן מסרב לנגן. באנדרואיד אין CORS,
  והנגן פונה לספק ישירות.
- **MPEG-TS** — דפדפנים לא מנגנים ערוצי `.ts` גולמיים. ExoPlayer כן.

בנוסף, האפליקציה מכבדת `#EXTVLCOPT:http-user-agent` ו-`http-referrer` מהרשימה —
כותרות שדפדפן לא נותן לקוד להגדיר, ושחלק מהספקים דורשים.

## מקורות תוכן

| מקור | פרטים |
| --- | --- |
| כתובת M3U | הורדה ופירסור במכשיר, כולל תמיכה בקבצים דחוסים (gzip) |
| קובץ מקומי | בחירת קובץ מהמכשיר או הדבקת תוכן M3U |
| Xtream Codes | התחברות ל-`player_api.php`: ערוצים, קטגוריות, ספריית סרטים ומדריך שידורים אוטומטי |

רשימות, מועדפים והיסטוריית צפייה נשמרים ב-`SharedPreferences` במכשיר בלבד.

## תכונות

- נגן Media3/ExoPlayer: HLS, DASH, MPEG-TS ו-VOD, עם התאוששות שקטה מניתוקים.
- חיפוש, קטגוריות, סינון שידור חי / סרטים, מועדפים ורשימת אחרונים.
- מדריך שידורים XMLTV: מה משודר עכשיו, מה אחר כך ופס התקדמות.
- פריסה מסתגלת: במסך רחב (טלוויזיה, טאבלט לרוחב) הרשימה לצד הנגן, בטלפון מעליה.
- מסך מלא עם חזרה בכפתור Back, וניווט D-pad לשלט.
- ערוצי גיבוי מקופלים לתוך הערוץ שהם מגבים — ראו למטה.
- חזרה אחורה בשידור (catch-up) בערוצים שהפורטל שומר — ראו למטה.
- התחברות מהטלפון בסריקת קוד, במקום להקליד סיסמה עם השלט — ראו למטה.

## התחברות מהטלפון

להקליד סיסמה של פורטל עם ארבעה חצים ו-OK זה הדבר הגרוע ביותר שהאפליקציה מבקשת,
והוא גם הדבר הראשון שהיא מבקשת. אז הטלוויזיה מפסיקה לבקש:

1. במסך המקורות, בלשונית Xtream, לוחצים **"מילוי מהטלפון"**.
2. הטלוויזיה מרימה שרת קטן ברשת המקומית ומציגה את הכתובת אליו כקוד QR.
3. סורקים עם מצלמת הטלפון, ומקבלים טופס רגיל עם מקלדת רגילה.
4. "שלח לטלוויזיה" — הפרטים עוברים ישירות, והטלוויזיה מתחברת לבד.

**מה לא קורה כאן:** אין שירות באמצע, אין חשבון, ושום דבר לא יוצא מהבית. הטופס
מוגש מהטלוויזיה עצמה אל הטלפון שעל אותה רשת, והפרטים נשמרים בדיוק היכן שהיו
נשמרים אילו הוקלדו בשלט — על המכשיר בלבד.

**המחיר, במפורש:** כל עוד הקוד על המסך, הטופס נגיש לכל מי שנמצא על אותה רשת
ביתית ויודע את הכתובת. לכן הכתובת נושאת סוד אקראי בן עשרה תווים, השרת עונה כלום
למי שלא נושא אותו, והוא נסגר ברגע שהחלון נסגר או שהפרטים התקבלו. התעבורה היא HTTP
רגיל בתוך הרשת הביתית — בלי תעודה אין HTTPS, וזה השיקול שנבחר במודע.

אם הקוד לא נסרק — הכתובת מוצגת גם כטקסט, והיא קצרה מספיק להקלדה בדפדפן של הטלפון.

**בטיזן זה לא קיים, ולא בגלל שלא נכתב:** אפליקציית ווב של Tizen לא יכולה להאזין
לחיבור נכנס — אין לה API לכך. כדי לעשות את זה שם צריך שירות נייטיב ארוז לצד
האפליקציה, שזו חבילה מסוג אחר עם אותה בעיית חתימה. בטלוויזיות סמסונג אפשר בינתיים
להקליד במקלדת של הטלפון דרך אפליקציית SmartThings, שמשמשת כמקלדת לשלט.

## חזרה אחורה בשידור

פאנל Xtream מדווח לכל ערוץ אם הוא שומר אותו (`tv_archive`) ולכמה ימים. איפה
שהוא שומר, אפשר לחזור אחורה בשתי דרכים: כפתור החזרה בשורת הפקדים, שמוריד את
התמונה לחצי שעה אחורה ומשם זה כבר הקלטה רגילה שאפשר לגלול בה; ולחיצה על תוכנית
שכבר שודרה בלוח שמתחת לתמונה.

הכפתור נמצא על **כל** ערוץ חי, גם כשהפורטל לא שומר אותו — אז הוא מעומעם, ולחיצה
עליו אומרת "הפורטל לא שומר את הערוץ הזה". זה בכוונה: כפתור שנעלם הופך תכונה
שהמנוי פשוט לא כולל לתכונה שנראית שבורה, ואי אפשר להבדיל בין השתיים.

## ערוצי גיבוי

ספקים מוסיפים לערוץ פיד גיבוי, ומפרסמים אותו כערוץ בפני עצמו מיד אחרי הערוץ
עצמו: "קשת 12", ואחריו "קשת 12 גיבוי", ואחריו "קשת 12 גיבוי 2". על מסך טלוויזיה
אלה שלושה אריחים זהים למראה, שרק לחיצה עליהם מגלה מי מהם חי.

באפליקציה גיבוי הוא לא ערוץ אלא **עוד דרך להגיע לאותו ערוץ**:

- הרשימה מציגה את הערוץ **פעם אחת**, עם סימון קטן (`+2`) שאומר כמה דרכים יש אליו.
- הנגן **נופל אחורה לבד**: כשהפיד הראשי לא עונה הוא ממשיך לגיבוי הבא בלי לשאול,
  ואומר בשורה אחת "עבר לגיבוי 1" כדי שלא יהיה נסתר.
- **בחירה ידנית** יושבת בנגן, בכפתור "מקורות": כל פיד מופיע שם תחת השם שהספק נתן
  לו, כך שקיפול שגוי גלוי במקום להיות מוסתר.
- **מה שעבד נזכר**: אם הגיבוי הוא זה שניגן, הערוץ ייפתח עליו בפעם הבאה. פיד ראשי
  שמת לשבוע הופך בשקט לפיד שכבר לא מנסים קודם.

הכלל צר בכוונה, כי קיפול מוטעה מסתיר ערוץ — וזה גרוע מהעומס שהוא פותר. גיבוי
חייב **להגיד** שהוא גיבוי: בשם ("גיבוי", "backup"), בקטגוריה, או בכך שהוא אותו שם
בדיוק עם מספר אחריו. "ספורט 1" ו-"ספורט 2" הם שני ערוצים ונשארים שניים; "קשת 12"
ו-"קשת 12 2" הם אחד, כי השם המשותף להם הוא בעצמו ערוץ ברשימה. גיבוי שהערוץ שלו
לא נמצא ברשימה נשאר ערוץ בפני עצמו — שום דבר לא נעלם.

## כשערוץ לא עולה

ספקים לא עקביים לא רק לגבי הפורמט אלא גם לגבי הכתובת עצמה. פאנל Xtream מגיש את
אותו ערוץ ב-`/live/USER/PASS/ID.m3u8`, ב-`ID.ts` וב-`ID` בלי סיומת — ולעיתים
קרובות רק חלק מהן מופעלות. רשימה שנותנת דווקא את כתובת ה-HLS בזמן שהיא כבויה
נראית בדיוק כמו ערוץ מת: השרת עונה 200 עם דף HTML.

לכן הנגן לא סומך על מה שהרשימה נתנה, אלא עובר על סולם: הסיומת שבכתובת, HLS
מאולץ, בלי רמז בכלל (שהבייטים יחליטו), אחר כך אותו ערוץ בנקודות הקצה האחרות של
הפאנל, ולבסוף שוב עם User-Agent של דפדפן — יש CDN-ים שמגישים רק למי שנראה כמו
דפדפן. כל שלב נכשל בבקשה אחת, אז המעבר מהיר. רק אם כל השלבים נכשלו מוצגת שגיאה, ולצדה קוד התקלה המדויק (ואם הייתה
תשובת HTTP — הסטטוס שלה), כדי שאפשר יהיה להבדיל בין ערוץ מת, חסימה גאוגרפית
ובעיה באפליקציה. במסך השגיאה יש גם כפתור לפתיחת הערוץ בנגן חיצוני כמו VLC.

ברשימות ציבוריות גדולות חלק ניכר מהערוצים פשוט מתים — כדאי לנסות כמה ערוצים
לפני שמסיקים שמשהו באפליקציה שבור.

## שלט Android TV

| מקש | פעולה |
| --- | --- |
| למעלה / למטה | במסך מלא — ערוץ קודם / הבא. כשהרשימה על המסך הם ממשיכים לנווט בה כרגיל |
| Channel Up / Channel Down | ערוץ הבא / הקודם, מכל מקום באפליקציה |
| הבא / הקודם (מקשי מדיה) | ערוץ הבא / הקודם |
| OK | פתיחת פקדי הנגן |
| Back | יציאה ממסך מלא |

מקשי הערוץ הייעודיים תמיד מחליפים ערוץ, אבל ה-D-pad נתפס רק במסך מלא — אחרת הוא היה
גוזל מהרשימה את הניווט שלה.

## בנייה

כל דחיפה מריצה את הבדיקות ובונה APK ב-GitHub Actions
(`.github/workflows/android.yml`). ה-APK מחכה כ-artifact בשם `telohim-debug-apk`
בתוך הריצה — פותחים את הריצה בלשונית Actions ומורידים משם.

מקומית:

```sh
./gradlew testDebugUnitTest   # בדיקות הפרסרים והסינון
./gradlew assembleDebug       # app/build/outputs/apk/debug/app-debug.apk
```

דורש JDK 17 ו-Android SDK 35.
